1. Introduction & System Overview

TransitOps is a centralized, real-time fleet operations management platform built for logistics companies. It solves four critical problems in a single unified system:

🗺
"Where Is My Cargo?"
Live GPS streaming + interactive Leaflet maps so clients track deliveries in real time.
🚛
Empty Miles Problem
Shared Capacity Marketplace — publish spare truck space for co-loading and maximize ROI per trip.
⚠️
Compliance Risks
Automated dispatch gating blocks expired licenses, suspended drivers, and in-shop vehicles.
💰
Financial Chaos
Centralized analytics computing Vehicle ROI, fuel efficiency, and maintenance burn rates.

2. System Requirements & Installation

Prerequisites

SoftwareMin. VersionPurpose
Node.jsv18+Backend runtime and frontend toolchain
npmv9+Package manager
PostgreSQLv14+Primary relational database

Setup Steps

Create the database
psql -U postgres -c "CREATE DATABASE transitops;"
Run the schema migration
psql -U postgres -d transitops -f database\schema.sql
Load seed / demo data (recommended)
psql -U postgres -d transitops -f database\seed.sql
Install and start the backend API
cd backend && npm install && npm start
# Runs on http://localhost:5000
Install and start the frontend
cd frontend && npm install && npm start
# Runs on http://localhost:3000

Real-Time GPS Flow

Driver clicks "Go Live"
  │
  ├─ Device GPS → emit('driverLocation', { trip_id, lat, lng })
  │                              │
  │                   Backend relays instantly (no DB write)
  │                              │
  └─ All tracker viewers ← emit('trackingUpdated', { lat, lng, isLive: true })
ℹ️
Live vs. PinnedLive GPS frames are relayed in real-time memory via Socket.io for zero-latency delivery — they are NOT written to the database. Only manually pinned checkpoints (Pin Location) are persisted.

10. Dispatch & Trips — The Trip Lifecycle

Route: /trips · Access: Fleet Manager (full), Driver (tracking actions)

10.1 Trip State Machine

Draft→ Dispatch → Dispatched→ Complete → Completed
Draftor Dispatched→ Cancel → Cancelled
TransitionAutomatic Side Effects
Draft → DispatchedVehicle & Driver → On Trip · Sets dispatched_at timestamp
Dispatched → CompletedVehicle & Driver → Available · Updates odometer · Creates fuel log
Any → CancelledVehicle & Driver → Available

10.2 Creating a Dispatch (Draft)

Click Create Dispatch (top-right of Trips page).
Fill in: Source Depot, Destination, Driver (only Available shown), Vehicle (only Available shown), Planned Distance (KM), Cargo Weight (KG).
The Payload Gauge bar shows capacity usage visually. The button is disabled if cargo weight exceeds vehicle capacity.
Click Schedule Draft. The trip appears with a Draft status badge.

10.3 Live GPS Streaming (Go Live)

On a Dispatched trip, click Go Live.
Allow location permission in the browser prompt.
GPS coordinates are reverse-geocoded and streamed via WebSocket to all shipper tracking viewers in real time. The button turns into a pulsing red Stop Live.
Click Stop Live to end the GPS session.

10.4 Manual Location Checkpoint (Pin Location)

Use when continuous GPS is not practical (poor connectivity, driver breaks).

FieldDescription
Location NameDescriptive name of the current location (e.g., Hosur Toll Plaza)
Latitude / LongitudeAuto-filled from device GPS, or enter manually
Statusin_transit · loading · unloading · arrived · delayed
NotesOptional context (e.g., "Traffic jam on NH44, delayed 45 min")

Checkpoints are saved to the database and broadcast via WebSocket to the shipper tracker instantly.

10.5 Sharing Spare Capacity

On a Dispatched trip with unused cargo space, click Share Capacity. Enter route source, destination, optional intermediate stops, departure time, ETA, and price per KG. Click Publish Route to list it in the Shared Cargo Marketplace.

10.6 Generating a Tracking Link for Clients

Click Open Tracker on a dispatched trip — the public URL is copied to your clipboard automatically and opens in a new tab. Share it with your client via WhatsApp, email, or SMS. No login required for the client.

10.7 Completing a Trip

On a Dispatched trip, click Complete.
Enter the Final Odometer Reading (KM) (auto-suggested) and Fuel Consumed (Liters).
Click Complete & Release. Vehicle and driver are automatically released to Available, odometer is updated, and a fuel log is created.

11. Maintenance Center

Route: /maintenance · Access: Fleet Manager only

Opening a maintenance file automatically sets the vehicle to In Shop and removes it from all dispatch dropdowns.

11.1 Scheduling a Maintenance File

Click Schedule Maintenance.
Select vehicle, choose type (Preventive = routine / Corrective = repair), set schedule date, optional estimated cost, and description of work.
Click Schedule Service. Vehicle status immediately changes to In Shop.

11.2 Closing a Maintenance File

Find the open maintenance log and click Close File.
Enter the final actual cost (INR) when prompted and click OK.
The log is marked closed and the vehicle is immediately restored to Available.

16. Business Rules & Automated Gating

TransitOps enforces all the following rules automatically — both via filtered dropdowns on the frontend and validated on the server-side API.

RuleWhat It Prevents
Vehicle Dispatch GateVehicles with status In Shop or Retired cannot be selected for a new trip
Driver Compliance GateDrivers with expired licenses or Suspended status cannot be assigned to trips
Double AssignmentDrivers or vehicles already On Trip cannot be assigned to another trip simultaneously
Payload CapacityCargo weight must not exceed the vehicle's maximum load capacity (KG)
Trip → DispatchedSets vehicle & driver to On Trip automatically
Trip → CompletedReleases both to Available, updates odometer, creates fuel log
Trip → CancelledReleases vehicle & driver back to Available
Maintenance → OpenCreating an open log sets vehicle to In Shop
Maintenance → ClosedClosing a file restores vehicle to Available

18. Role-by-Role Daily Workflows

🚛 Fleet Manager

  1. Check Dashboard KPIs for overnight changes
  2. Close completed maintenance files
  3. Dispatch ready Draft trips
  4. Create new dispatch orders as needed
  5. Monitor live trips via Open Tracker
  6. Log fuel receipts & expenses
  7. Review weekly ROI & export CSV

👨‍✈️ Driver

  1. Check Dashboard for trip summary
  2. Go to My Trips → find Dispatched trip
  3. Click Go Live → allow location permission
  4. At stops → Pin Location checkpoint
  5. On arrival → click Complete
  6. Enter odometer + fuel consumed
  7. Log any separate fuel fill-ups

🛡 Safety Officer

  1. Check Dashboard active driver count
  2. Open Drivers → scan for expiry badges
  3. Flag drivers with safety score < 6.0
  4. Contact drivers for license renewal
  5. Report compliance issues to management

💹 Financial Analyst

  1. Check fleet utilization % (target ≥70%)
  2. Review ROI ledger — flag red-badge vehicles
  3. Check Fuel Economy chart for outliers
  4. Audit Fuel & Expenses ledger entries
  5. Export CSV for weekly/monthly accounts

ProblemCauseSolution

ProblemSolution

General Tips
  • Toast notifications appear top-right for every action — read them to confirm success or see error details.
  • Dropdowns are pre-filtered — only eligible options are shown. If something is missing, check its current status.
  • Dashboard updates automatically via WebSocket — no need to refresh the page.
  • The /track route is fully public — share it freely with clients. No account needed.
